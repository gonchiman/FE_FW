# テンプレート作成の共通手順

このプロジェクトのUI・配色・グラフなどをテンプレート化・標準化するとき、または既存テンプレートを更新するときに適用する。ユーザーが対象範囲や保存形式を指定した場合は、その指定を優先する。

## 基準を整理する

- 採用された案と現在の実装を確認し、対象範囲、固定する仕様、利用ごとに変える入力を整理する。同じ用途の既存テンプレートがあれば更新する。
- テンプレート化を理由に、採用済みの見た目、色の意味、計算、動作を変更しない。結果に影響する基準を判断できない場合は、その点を確認する。

## 仕様・共通部品・見本を揃える

以下はプロジェクトルートからの配置例。既存の構成がある場合はそれに合わせる。

| 成果物 | 保存先と役割 |
| --- | --- |
| 仕様 | `docs/<テーマ名>/README.md`。適用範囲、固定仕様、可変部分、使い方、確認方法を記載する |
| 共通部品・定義 | `src/components/` や `src/lib/`。利用側が参照する共通の定義元にする |
| 見本 | `docs/<テーマ名>/examples/`。対象に合った画像・入力例・出力例を保存する |
| 参照の入口 | `AGENTS.md`。使う作業と完成した仕様への相対リンクを登録する |

- 既存の共通部品や定義を優先し、ページごとに同じ定義をコピーしない。コードが定義元の値は、仕様書に転記せず参照先を示す。
- コードを必要としない対象では、ひな形・設定・手順を保存する。
- 見本の文字や数値は例として扱う。採用済みデザインの参考か、実装から再生成する確認用かを明記する。
- 確認用の見本は実装・実際の出力から作り、生成方法と更新手順を残す。
- 仕様には現在の適用箇所と未適用箇所を記載する。既存箇所への適用は依頼された範囲で行う。

## 確認する

- 仕様・共通定義・見本の一致と、相対リンクの実在を確認する。
- 見た目は実際に描画して確認し、画像保存を扱う場合は保存した画像も確認する。対象に応じて長い文字列やデータ量、表示サイズの違いを確認する。
- 完了報告では保存場所、検証結果、適用した範囲を示す。テンプレートの保存と既存箇所への適用を区別する。
